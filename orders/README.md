## Запуск

Из корня репозитория:

```sh
make up
make scenarios TASK=1
make scenarios TASK=2
```

Сервис использует `DATABASE_URL`, `PAYMENT_URL`, `INVENTORY_URL` и `EVENTS_URL`.
Порт задаётся через `PORT`, по умолчанию 8080. Схема БД создаётся при запуске.

## Обработка

Заказ сохраняется в PostgreSQL, клиент получает `201` со статусом `pending`.
Резервирование товара, оплата и отправка событий выполняются отдельными
асинхронными обработчиками. Сервис рассчитан на один экземпляр.

Платёж повторяется с одним ключом идемпотентности. При неизвестном результате
проверяются списания по заказу. При недоступности Payment обработчик оплаты
делает паузу на 5 секунд. Отказ банка `402` приводит к снятию резерва и `rejected`.

Статус `paid` и исходящее событие сохраняются одной транзакцией.
Неотправленные события повторяются с тем же идентификатором.

Доставки записываются в журнал с уникальным `event_id`. Повторное событие
не добавляет баллы. Баланс вычисляется суммой начислений покупателя.

## Тесты

```sh
cd orders
python -m pip install -r requirements.txt
python -m unittest -v
```

Для интеграционных тестов задайте `TEST_DATABASE_URL` отдельной тестовой БД.
Перед каждым тестом таблицы сервиса в ней очищаются. Без этой переменной
интеграционные тесты пропускаются.
